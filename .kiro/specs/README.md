# Specs

Kiro specs live here, one directory per feature. A spec is the requirements, design and task
breakdown Kiro works from, and **these files are a graded submission artifact** for this challenge:

> "Include your Kiro specs and/or prompt markdown files, steering files (or equivalent project
> guidance), and any hooks used for testing or documentation. Disclose any substantial manual changes
> you made to Kiro-generated code."

So treat them as deliverables, not scratch. Keep them in the repo as they evolve rather than
reconstructing a tidy version at the end, and when you override Kiro by hand, note it here or in the
README rather than silently editing the generated file.

Suggested layout, which is Kiro's own default:

```
.kiro/specs/<feature-name>/
├── requirements.md
├── design.md
└── tasks.md
```
